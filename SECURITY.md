# Security policy

## Supported versions

Security fixes apply to the latest version on `main`.

## Reporting a vulnerability

Do not place credentials, production IP addresses, patient data, employee data, or exploit details in a public issue. Use GitHub private vulnerability reporting when available. Otherwise, open an issue titled `Private security contact requested` without sensitive technical detail.

Include the affected commit, security impact, synthetic reproduction steps, and any proposed mitigation.

## Data policy

This repository accepts synthetic data only. Do not commit real authentication logs, identity records, credentials, healthcare information, or production network identifiers.

## Security scope

Reports are in scope when they concern parser bypasses, unsafe file handling, alert-integrity failures, detection-evasion defects, workflow vulnerabilities, or unintended disclosure of input data.
